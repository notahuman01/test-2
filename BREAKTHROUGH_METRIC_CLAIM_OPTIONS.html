Baseline Pipeline Reference

The baseline TAG derivation has this active flow:

  1. 1. BLIP-2/Q-Former video features \(F \in \mathbb{R}^{T \times 32 \times 256}\).
  2. 2. Anchor text query vector \(q\).
  3. 3. Token cosine matrix \(S_{i,j} = \hat{f}_{i,j}^{T}q\).
  4. 4. Hard max raw timeline:

$$ s_i = \max_j S_{i,j} $$

  1. 5. Winning-token index selection:

$$ j_i^* = \arg\max_j S_{i,j} $$

  1. 6. Raw winning token features for clustering:

$$ f_{i,j_i^} = F[i,j_i^,:] $$

  1. 7. Temporal pooling, masking, Box-Cox, TCKMeans proposal generation.
  2. 8. Static inner-minus-outer proposal scoring:

$$ S_p = \text{mean}(a_{inside}) - \text{mean}(a_{outside}) $$

  1. 9. Dynamic boundary refinement as a start-boundary correction bridge.
  2. 10. Consensus voting / Soft-NMS-style proposal selection.

Cycle16 keeps the strong TAG spine, but replaces four decision points: timeline weighting, proposal representation/scoring, refinement behavior, and voting.

Option 1: Raw Timeline Upgrade

Best when introducing the onset contribution.

Baseline

The baseline raw timeline is a hard max over visual tokens:

$$ s_i = \max_j S_{i,j} $$

This is simple and strong, but it treats a flat confident plateau and a rising action onset the same if their absolute similarity is equal.

Cycle16 Upgrade

Cycle16 keeps the hard max timeline but applies a confidence-gated rising-edge multiplier:

$$ s_i' = s_i \left(1 + \beta \cdot g_i^{+} \cdot h_i^{conf-contrast}\right) $$

where:

  • - \(g_i^{+}\) is the positive temporal gradient only.
  • - \(h_i^{conf-contrast}\) is high only when the frame is both confident and locally above its neighborhood.

Core parameters:

beta: 0.10 / 0.35
onset_gradient_mode: positive
onset_norm_percentile: 95.0
onset_smooth_kernel: 5
onset_gate_mode: confidence_contrast

Claim wording:

We preserve TAG's hard-max raw similarity timeline but make it boundary-aware: cycle16 amplifies only confident, locally contrastive rising edges before masking and proposal generation. This turns the baseline \(s_i=\max_j S_{i,j}\) into an onset-sensitive timeline while retaining the zero-shot/no-LLM TAG spine.

Metric attachment:

This aligned onset path contributes to a +1.94 mIoU gain on Charades-STA and +1.30 mIoU on ActivityNet Captions over the TAG baseline.

Option 2: Clustering Representation Upgrade

Best when explaining why cycle16 keeps hard tokens but changes proposal geometry.

Baseline

The baseline selects the winning token index:

$$ j_i^* = \arg\max_j S_{i,j} $$

Then it clusters the corresponding raw, unnormalized feature:

$$ f_{i,j_i^} = F[i,j_i^,:] $$

The baseline rationale is that raw magnitude may help clustering.

Cycle16 Upgrade

Cycle16 still uses the same winning token index, but clusters normalized winning-token features:

$$ z_i = \frac{f_{i,j_i^}}{\|f_{i,j_i^}\|_2} $$

Then time is appended and temporal pooling is applied as usual:

$$ u_i = [z_i, i/T] $$

Core parameters:

cluster_feature_source: normalized
temporal_window_size: 21
window_radius: 7
kmeans_k: 12

Claim wording:

Cycle16 keeps TAG's exact hard-token selection but changes the clustering representation from raw token magnitude to normalized semantic direction. This makes temporal clustering depend less on feature norm artifacts and more on semantic consistency through time.

Metric attachment:

Under the full aligned recipe, this representation contributes to improvements on every reported Charades-STA and ActivityNet metric.

Option 3: Proposal Scoring Upgrade

Best when explaining Cohen's d.

Baseline

The baseline proposal score is raw inner-minus-outer contrast:

$$ S_p = \mu_{inside} - \mu_{outside} $$

This rewards proposals whose inside average is higher than the outside average, but it does not account for score variance.

Cycle16 Upgrade

Cycle16 uses Cohen's d effect size:

$$ S_p^{cycle16} = \frac{\mu_{inside} - \mu_{outside}}{\sigma_{pooled} + \epsilon} $$

The proposal is not just rewarded for a higher inside mean; it is rewarded when the inside/outside separation is large relative to the distribution spread.

Core parameters:

scoring_type: cohens_d
argmax_bonus_alpha: 0.50 / 0.10
alpha: 0.0
temp: 0.0

Claim wording:

Cycle16 replaces TAG's raw inner-minus-outer proposal score with an effect-size score. Cohen's d asks whether a proposal is statistically separated from its temporal context, not merely whether its inside average is higher.

Metric attachment:

The final aligned effect-size lane improves R@0.5 by +3.73 on Charades-STA and +0.71 on ActivityNet Captions over the TAG baseline.

Option 5: Voting Upgrade

Best when explaining final proposal selection.

Baseline

The baseline voting description is consensus-based:

$$ \hat{S}_j = \sum_i \text{IoU}(p_i,p_j)^\gamma S_i $$

This rewards agreement among overlapping proposals.

Cycle16 Upgrade

Cycle16 selects with DA-NMS:

$$ \hat{S}_j = \sum_i \text{IoU}(p_i,p_j)^\gamma S_i D_i^{\alpha_D} $$

where \(D_i\) is the internal proposal density and \(\alpha_D\) controls how strongly density affects voting power.

In plain terms, a proposal should not get full voting strength just because it overlaps many other proposals. It should also be internally compact: the frames inside the proposal should contain consistently high action evidence, not just one sharp peak surrounded by weak background. DA-NMS adds this density term to distinguish tight action spans from wide, diluted spans.

The density term can be understood as:

$$ D_i \approx \frac{\text{mean action score inside }p_i}{\text{max action score inside }p_i} $$

So:

  • - \(D_i \approx 1\): the proposal is dense; most frames inside it are strongly action-like.
  • - \(D_i \ll 1\): the proposal is diluted; it may contain one good peak but too much weak/background context.

The exponent \(\alpha_D\) is the density strength:

$$ D_i^{\alpha_D} $$

  • - \(\alpha_D = 0\): density has no effect, because \(D_i^0 = 1\). This collapses back toward ordinary overlap voting.
  • - \(\alpha_D = 1\): density is applied directly. A proposal with density \(0.5\) gets half voting power.
  • - \(\alpha_D > 1\): density becomes stricter. A proposal with density \(0.5\) and \(\alpha_D=2\) gets \(0.25\) voting power.

Cycle16 uses the code default:

$$ \alpha_D = 1.0 $$

This means DA-NMS applies a direct, interpretable density penalty without making the voting stage too aggressive.

Core parameters:

voting_method: da_nms
nms_gamma: 0.6
da_nms_alpha: 1.0
scoring_type: cohens_d

Claim wording:

Cycle16 upgrades TAG's consensus selection with density-aware voting. Proposals still vote through temporal overlap, but low-density spans lose influence, reducing the chance that broad background-heavy boxes dominate the final prediction.

Metric attachment:

Under the aligned DA-NMS lane, all 8 reported metrics improve across Charades-STA and ActivityNet Captions versus the TAG baseline.
