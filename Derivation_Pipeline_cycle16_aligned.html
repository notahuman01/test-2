This document derives the active pipeline used by the cycle16 aligned ActivityNet/Charades architecture.

It is intentionally slimmer than analysis/deep_analysis_v0.5.2/Derivation_Pipeline_v0.5.2.md: only modules that are active in the cycle16 YAMLs are included. Template ensembles, semantic negatives, quality negatives, query decomposition, boundary prompts, hybrid token softness, legacy v00 start refinement, WBF, PSS, adaptive gamma/k, and OOD padding are not part of this architecture.

2. Text And Visual Encoding

The input query is encoded directly as one anchor embedding:

$$ q = \frac{\text{TextEncoder}(y)}{\|\text{TextEncoder}(y)\|_2} $$

No boundary prompts are active, so there is no separate start/end text track. No template ensemble or synonym averaging is active in this path.

For each video frame \(i\), BLIP-2/Q-Former features provide 32 visual tokens:

$$ F_i = \{f_{i,1}, f_{i,2}, \dots, f_{i,32}\}, \quad f_{i,j} \in \mathbb{R}^{256} $$

Each token is normalized:

$$ \hat{f}_{i,j} = \frac{f_{i,j}}{\|f_{i,j}\|_2} $$

The token-query cosine matrix is:

$$ S_{i,j} = \hat{f}_{i,j}^{\top} q $$

3. Hard Token Timeline

Because alpha: 0.0 and temp: 0.0, the hybrid token selector is bypassed. The active timeline is the exact hard maximum over the 32 visual tokens:

$$ s_i = \max_j S_{i,j} $$

This is important for alignment: ActivityNet and Charades now share the same hard-token path. The earlier Charades hybrid-softness story is removed from the final aligned architecture.

4. Positive Gated Onset Weighting

The cycle16 onset module does not use the old absolute-gradient onset. It uses rising-only gradients:

$$ g_i = \max(s_i - s_{i-1}, 0) $$

The gradient is padded back to length \(T\), then smoothed by a width-5 box filter:

$$ \tilde{g}_i = \frac{1}{5}\sum_{r=-2}^{2} g_{i+r} $$

It is normalized by the 95th percentile:

$$ \bar{g}_i = \text{clip}\left(\frac{\tilde{g}_i}{Q_{0.95}(\tilde{g})}, 0, 1\right) $$

Confidence-Contrast Gate

The gate keeps onset boosts concentrated where the query score is high and locally above its neighborhood.

First normalize the score track to unit scale:

$$ c_i = \text{normalize}_{0,1}(s_i) $$

Compute a local mean with onset_gate_kernel: 7:

$$ \mu_i^{local} = \frac{1}{7}\sum_{r=-3}^{3} s_{i+r} $$

Then compute positive local contrast:

$$ \ell_i = \text{normalize}_{0,1}\left(\max(s_i - \mu_i^{local}, 0)\right) $$

The active confidence_contrast gate is:

$$ h_i = \sqrt{\text{clip}(c_i \ell_i, 0, 1)} $$

With onset_gate_strength: 1.0, the gate fully modulates the normalized rising gradient:

$$ g_i^{gated} = \bar{g}_i h_i $$

No post-gate renormalization is used:

$$ \text{onset\_renorm\_after\_gate} = false $$

The final onset weight is:

$$ w_i = 1 + \beta g_i^{gated} $$

The timeline entering masking becomes:

$$ s_i' = s_i w_i $$

Dataset-native beta changes only the strength:

  • - ActivityNet: \(\beta = 0.10\)
  • - Charades: \(\beta = 0.35\)

5. Masking And Box-Cox Adjustment

The foreground mask uses the fixed threshold:

$$ m_i = \mathbb{1}(s_i' > 0.2) $$

The scores_masking stage then cleans the mask and returns the masked frame indices. The active score vector after masking is:

$$ x = \{s_i' \mid m_i = 1\} $$

Box-Cox alignment adjustment is active because disable_boxcox is not enabled:

$$ a_i = \begin{cases} \frac{x_i^\lambda - 1}{\lambda}, & \lambda \neq 0 \\ \log(x_i), & \lambda = 0 \end{cases} $$

The adjusted score vector \(a\) is what proposal scoring consumes.

6. Normalized-Feature Temporal Clustering

For clustering, the system first picks the best token index per frame:

$$ j_i^* = \arg\max_j S_{i,j} $$

Because cluster_feature_source: normalized, clustering uses normalized semantic-token features rather than raw unnormalized features:

$$ z_i = \hat{f}_{i,j_i^*} $$

The relative timestamp is appended:

$$ u_i = [z_i, i/T] $$

Temporal smoothing is applied with temporal_window_size: 21, and temporal K-Means uses:

$$ K = 12 $$

Cluster transitions define candidate temporal regions. The proposal generator expands contiguous cluster regions using the dataset-native search geometry:

  • - ActivityNet: prior: 1.0, cand_num: 8
  • - Charades: prior: 0.5, cand_num: 12

7. Cohen's d Proposal Scoring

Each proposal \(p = [b,e)\) is scored using the adjusted score vector \(a\). Let \(I_p\) be scores inside the proposal and \(O_p\) be scores outside it:

$$ \mu_I = \text{mean}(I_p), \quad \mu_O = \text{mean}(O_p) $$

Let the pooled standard deviation be:

$$ \sigma_p = \sqrt{ \frac{(|I_p|-1)\sigma_I^2 + (|O_p|-1)\sigma_O^2} {|I_p| + |O_p| - 2} } $$

The active scoring type is cohens_d:

$$ \text{score}(p) = \frac{\mu_I - \mu_O}{\sigma_p + \epsilon} $$

Argmax Inclusion Bonus

The proposal score is multiplied if the proposal contains the global score peak:

$$ \text{score}'(p) = \text{score}(p) \left(1 + \alpha_{argmax}\mathbb{1}[\arg\max_i a_i \in p]\right) $$

Dataset-native values:

  • - ActivityNet: \(\alpha_{argmax}=0.50\)
  • - Charades: \(\alpha_{argmax}=0.10\)

8. Modern Dynamic Refinement

Legacy v00 start refinement is off:

$$ \text{v00\_start\_refinement\_compat} = false $$

The active refinement is the modern dynamic lane:

enable_dynamic_refinement: true
dynamic_refinement_mode: both
dynamic_refinement_ths: 0.002
dynamic_refinement_max_end_ratio: 0.35

The same get_dynamic_scores onset-pointer mechanism is computed in two directions:

  • - forward track for start refinement
  • - reversed track for end refinement

For start refinement, a proposal beginning inside a sustained rise can expand backward to the launch point of that rise.

For end refinement, the reversed score track lets the proposal end expand to a corresponding semantic boundary. The end expansion is capped:

$$ \Delta e \leq 0.35 \cdot |p| $$

The default behavior is expand_only, so this architecture is conservative: it can widen proposals to recover missing action extent, but it does not shrink them in the active cycle16 config.

9. DA-NMS Voting

After refinement, proposals are selected with voting_method: da_nms.

For each candidate proposal \(p_j\), DA-NMS computes a density-aware consensus score:

$$ \hat{S}_j = \sum_i \text{IoU}(p_i, p_j)^\gamma S_i D_i^{\alpha_D} $$

where:

  • - \(S_i\) is the proposal score after refinement.
  • - \(D_i\) is the proposal internal density.
  • - \(\alpha_D = 1.0\) by default.
  • - \(\gamma = 0.6\) by default in the voting code path.

The proposal list is sorted by \(\hat{S}_j\), and the top proposal becomes:

$$ p_{final} = [t_{start}, t_{end}, \hat{S}] $$

11. Interpretation

The final aligned cycle16 architecture is a deliberately narrow story:

  1. 1. Build a hard maximum query timeline from BLIP-2/Q-Former tokens.
  2. 2. Boost only rising edges that are also confident and locally contrastive.
  3. 3. Mask and Box-Cox normalize the foreground score distribution.
  4. 4. Cluster normalized semantic-token features with time.
  5. 5. Score proposals by Cohen's d instead of raw inner-minus-outer contrast.
  6. 6. Expand proposal boundaries with modern dynamic start/end refinement.
  7. 7. Select by density-aware consensus voting.

The main architectural claim is now clean: ActivityNet and Charades use the same active module path. The remaining differences are dataset-native numeric strengths, not different modules.
