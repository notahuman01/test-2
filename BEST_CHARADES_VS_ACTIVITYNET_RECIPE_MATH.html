1. Raw Similarity Spine

Both datasets keep the TAG baseline hard-token spine.

Let \(F \in \mathbb{R}^{T \times 32 \times 256}\) be BLIP-2/Q-Former video features and \(q\) be the normalized text query. The token similarity matrix is:

$$ S_{i,j} = \hat{f}_{i,j}^{T}q $$

The frame timeline is the hard maximum:

$$ s_i = \max_j S_{i,j} $$

Because:

alpha: 0.0
temp: 0.0

the hybrid token scorer is bypassed on both datasets. This is a major change from the older Charades-only recipe, which used alpha=0.6 and temp=0.03.

2. Confidence-Contrast Rising-Onset Weighting

Cycle16 keeps the hard timeline but changes it before masking:

$$ s_i' = s_i \left(1 + \beta \cdot g_i^{+} \cdot h_i^{conf-contrast}\right) $$

where:

$$ g_i^{+} = \max(s_i - s_{i-1}, 0) $$

The gradient is smoothed with kernel 5 and normalized by the 95th percentile:

$$ \bar{g}_i = \text{clip}\left(\frac{\text{smooth}_5(g_i^+)}{Q_{0.95}}, 0, 1\right) $$

The confidence-contrast gate is:

$$ h_i^{conf-contrast} = \sqrt{ \text{clip}(c_i \ell_i, 0, 1) } $$

where \(c_i\) is normalized confidence and \(\ell_i\) is positive local contrast against a kernel-7 local mean.

Interpretation:

  • ActivityNet: \(\beta=0.10\), gentle onset boost.
  • Charades: \(\beta=0.55\), stronger boundary boost.

3. Masking And Box-Cox

Both datasets use the same foreground threshold:

$$ m_i = \mathbb{1}(s_i' > 0.2) $$

The masked score distribution is Box-Cox adjusted:

$$ a_i = \begin{cases} \frac{(s_i')^\lambda - 1}{\lambda}, & \lambda \neq 0 \\ \log(s_i'), & \lambda = 0 \end{cases} $$

The top-level gamma differs by dataset:

  • ActivityNet: gamma: 0.9
  • Charades: gamma: 0.2

4. Normalized Winning-Token Clustering

Both datasets select the winning token index:

$$ j_i^* = \arg\max_j S_{i,j} $$

The old baseline clusters raw winning-token features:

$$ f_{i,j_i^} = F[i,j_i^,:] $$

Cycle16 clusters normalized winning-token features:

$$ z_i = \frac{f_{i,j_i^}}{\|f_{i,j_i^}\|_2} $$

Then time is appended:

$$ u_i = [z_i, i/T] $$

Shared clustering geometry:

kmeans_k: 12
window_radius: 8
cluster_feature_source: normalized

Dataset-native proposal geometry:

ActivityNet: prior=1.0, cand_num=8, temporal_window_size=21
Charades:    prior=0.5, cand_num=12, temporal_window_size=13

5. Cohen's d Proposal Scoring

The older TAG baseline scores proposals with raw inner-minus-outer contrast:

$$ S_p^{baseline} = \mu_I - \mu_O $$

Cycle16 uses effect size:

$$ S_p^{cycle16} = \frac{\mu_I - \mu_O}{\sigma_{pooled} + \epsilon} $$

where:

$$ \sigma_{pooled} = \sqrt{ \frac{(|I|-1)\sigma_I^2 + (|O|-1)\sigma_O^2} {|I|+|O|-2} } $$

This rewards proposals whose inside distribution separates from outside context relative to variance, not just by raw mean difference.

The argmax inclusion bonus remains dataset-native:

$$ S_p' = S_p \left(1 + \alpha_{argmax}\mathbb{1}[\arg\max_i a_i \in p]\right) $$

Values:

  • ActivityNet: argmax_bonus_alpha: 0.50
  • Charades: argmax_bonus_alpha: 0.10

6. Modern Two-Sided Dynamic Refinement

The old ActivityNet-compatible start-only block is now off:

v00_start_refinement_compat: false

Both datasets use modern dynamic refinement:

enable_dynamic_refinement: true
dynamic_refinement_mode: both
dynamic_refinement_ths: 0.002
dynamic_refinement_max_end_ratio: 0.35

Conceptually:

$$ p=[a,b] \rightarrow p'=[a',b'] $$

where the start can expand to a dynamic launch point, and the end can expand using the reversed dynamic signal. End expansion is capped:

$$ \Delta b \leq 0.35 |p| $$

This replaces the older mismatch:

  • old Charades: modern dynamic refinement
  • old ActivityNet: v00 notebook start-shift compatibility

Cycle16 uses one refinement architecture for both.

7. DA-NMS Voting

The final selection uses density-aware NMS voting:

$$ \hat{S}_j = \sum_i \text{IoU}(p_i,p_j)^\gamma S_i D_i^{\alpha_D} $$

where \(D_i\) is proposal density. A useful approximation is:

$$ D_i \approx \frac{\text{mean action score inside }p_i} {\text{max action score inside }p_i} $$

So:

  • \(D_i \approx 1\): dense, compact proposal.
  • \(D_i \ll 1\): diluted proposal with weak/background context.

The density exponent controls how strongly density affects voting:

$$ D_i^{\alpha_D} $$

Cycle16 uses the code default:

da_nms_alpha: 1.0
nms_gamma: 0.6

At \(\alpha_D=1.0\), density directly scales proposal voting power. This reduces the influence of overly wide, low-density spans.

9. Practical Takeaway

The best current story is not "each dataset wants a different architecture." It is:

Use the same aligned TAG module path on both datasets, and let only dataset-native numeric strengths differ.

This is why cycle16 is cleaner than the older cycle12/cycle14 pairing. The modules are now aligned; the remaining differences are interpretable dataset geometry and strength parameters.
